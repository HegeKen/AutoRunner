# 一、小米超级岛通知体系介绍

**小米超级岛是一个持续服务与重要信息展示空间，帮助用户快速掌握服务进展并及时处理。其技术架构&产品方案是在焦点通知基础上的能力升级**

小米超级岛是为开发者提供的创新通知交互能力，可在用户当前应用上层开辟独立展示区域，实现后台服务的持续可视与即时交互。通过小米超级岛的接入，您的服务将满足以下体验：

- 服务常驻可见： 关键信息与进度状态全局展示，用户无需离开当前应用即可获取最新动态
- 服务外露适度： 支持选择需要常驻展示的服务类型，避免对用户过度打扰
- 信息注意力管理： 通过动态高亮设计，在需要时短时吸引用户关注，平衡提醒强度与使用体验
- 原地操作闭环： 支持展开详细信息面板并集成高频操作，用户无需跳转即可完成核心交互
**小米超级岛为用户创造了真正并行任务处理环境，同时为开发者提供了提升服务触达效率与用户粘性的全新机会。**

# 五、岛通知准入原则

请根据以下准入原则对所提报场景进行初步评估，自行评估符合后提报

**准入基础原则（以下两项均需满足）：**
标准1：有明确且有限的服务生命周期
服务进程必须有明确的开始触发条件和结束条件，且整个进程的持续时长不超过12小时。
标准2：确保信息价值，避免营销属性类场景接入
严格禁止任何以推广、广告、促活等为目的的营销属性通知接入。

**核心价值原则（满足基础条件后满足以下其一即可）：**
标准1：用户主动发起，符合履约预期
通知必须由用户明确的操作、预约等行为触发（*如打车、预售定金支付、设置提醒*），具有履约属性，符合用户的操作预期。
标准2：用户高度关注，需实时交互
信息是用户在当前时刻非常关注的，有反复查看进度或进行快捷操作（*如取消、修改、确认*）的需求。
标准3：错过后有严重后果的信息提醒
用户若错过并在有限时间内未处理，将导致实质性负面后果（*如经济、安全损失、错过重要行程、服务失效等*）。

**禁止通过的场景参考**

1. 长期常驻类场景： 无明确结束时间的服务（ 如“长期天气展示”“实时股价” ）、需持续展示超过12小时的进程；
2. 营销/推广类： 促销活动通知、广告推送、优惠券发放提醒、借款/理财类营销信息；
3. 无明确价值的静态信息： 纯告知类信息（ 如“应用已更新”、“剧集/小说更新”、“版本优化完成”、“优惠券到账” ）、无进度的纯状态展示（ 如“已登录”“已连接网络” ）；
4. 低价值高频打扰类： 社交软件普通消息（ 非重要交易/行程通知 ）、应用内常规互动提醒（ 点赞、评论 ）；
5. 重复接入场景： 航班/火车行程（ 由出行助手统一承接，第三方应用不得重复接入 ）、callkit语音视频通话场景场景（ 由callkit团队统一承接，第三方应用不得单独接入 ）、系统已覆盖的基础功能（ 如原生闹钟、系统倒计时 ）。
